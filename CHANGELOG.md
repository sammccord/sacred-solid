# sacred-solid

## 0.2.0

### Minor Changes

- c5e0d67: Move to Solid 2. The peer dependencies are now `solid-js` and `@solidjs/web` 2.0.0-rc.21 or newer, and Solid 1 is no longer supported. `BodyPortal` now uses Solid's `Portal`, so clicks inside portaled menus and modals reach their handlers. Rendered markup is unchanged except that `BarProgress` writes its attributes in React's order and the radar `<svg>` loses its redundant `xmlns` attribute.

## 0.1.0

### Minor Changes

- 8380205: `aug.border` and `aug.inlay` now default to theme colors and widths. Before, `border: true` drew a 4px border in `currentColor` and `inlay: true` drew a 3px inset in translucent grey, so every call site repeated a color. Now the border is `--theme-line-strong` at `--theme-line-width`, and the inlay is `--theme-surface-float` at `--theme-line-width` from the border. This is a deliberate visual change for any caller that passed `border: true`, `inlay: true`, or a width without a `bg`. Pass `bg`, `all` or the other options to keep the old look. Explicit options still win.
- 8380205: Add an optional `aug` prop to every component with a single DOM root. It applies augmented-ui clipped corners, borders and inlays through a typed object, and the augmented-ui stylesheet ships inside `sacred-solid/style.css`.
- 8380205: Every exported component that renders an element now takes `class`, merged with the library class by `classNames`. Components with several sibling roots put it on the one that visually owns them, `Accordion` on the header row, `Select` on its `section`, `ComboBox` on its `div`, `CanvasPlatformer` and `CanvasSnake` on the `div` around the canvas, `RadioButtonGroup` on each `RadioButton`. `Input` and `TextArea` now put `class` on the outer `div`, where the last release put it on the hidden field. Modals forward `class` to the card they render, and page templates forward it to their root. `Providers`, `ModalProvider`, `BodyPortal` and `DebugGrid` render no element and take none. `Table` takes `classes={{ body }}` for its `tbody`. Markup is unchanged when no class is passed. `docs/reference/class-targets.md` is generated from the sources and fails the docs test if a component stops reading `class`.
- 8380205: Behavior change in the cascade. Every sacred-solid stylesheet now sits in a cascade layer, `sacred.vendor` (augmented-ui), `sacred.base` (`global.css`, `global-fonts.css`), `sacred.aug`, `sacred.components` (every component module) and `sacred.themes` (`holo`, `acid`, `redline`). Each shipped file starts with the order statement `@layer sacred.vendor, sacred.base, sacred.aug, sacred.components, sacred.themes;`. Your unlayered CSS now beats all library CSS whatever the load order or specificity, including the library hover and focus states, so a plain `.x { color: red }` now beats the library `.x:hover`. Doubled selectors and import order tricks that beat a library class are no longer needed. To rank your own layers against the library, state `@layer reset, sacred, app;` before the library loads. Browsers without `@layer` support (before 2022) style nothing. `dist/styles/*.css` and `dist/themes/*.css` are now written by a post-pack step instead of being copied. The augmented-ui border and inlay defaults in `aug.css` now use `:where()` and win through the layer order.
- 8380205: Close the HUD gaps. `Accordion` takes `aug` and `theme`, which go on its header row. Its body row now gets its `padding-left: 1ch` from CSS (a class) instead of an inline style, so a caller class can override it. The computed padding is unchanged, the markup loses `style="padding-left: 1ch;"` and gains a class. `BarProgress` takes `style`, so a caller sets the solid height. `Navigation` takes `logo={false}` to render no logo button, the default markup is unchanged. `Tabs` items take `panel`, and `Tabs` renders the selected one with `role="tabpanel"` and wired `aria-controls` and `aria-labelledby`. `Tabs` is now controlled with `value` or uncontrolled with `defaultValue`, and `classes` gains `panel`. Define `panel` with a getter to build it only while its tab is selected. New `ScrollArea` scrolls vertically, with `fade` on the edges that can still scroll, `scrollbar` set to `native`, `hidden` or `rail`, and `classes` for `viewport`, `content`, `rail` and `thumb`. `Table` takes `classes={{ body }}`.
- 8380205: Callers can restyle components without descendant selectors. Every component that spread `rest` after its own `class` now merges the two with `classNames`, so a caller `class` no longer replaces the library class. This covers `Avatar` with children, `Badge`, `Block`, `Button`, `CodeBlock`, `Drawer`, `DropdownMenu`, `Grid`, `Indent`, `Input` and `TextArea` (the hidden field), `KeyHint`, `Popover`, `Row`, `RowEllipsis`, `RowSpaceBetween`, `SidebarLayout`, `Table`, `TableColumn`, `TableRow`, `Text`, `Tooltip` and `Window`. Markup is unchanged when no class is passed. A rule in your stylesheet that relied on replacing the library class now has to win by specificity or by loading later.
  
  Components with inner parts take `classes`, a `SlotClasses` object. `Panel` has `header`, `icon`, `title`, `meta` and `body`, and takes `padding` for the body. `KeyHint` has `cap` and `label`. `Accordion` has `header`, `icon`, `title` and `body`, and takes an `icon` function of the open state.
  
  `KeyHint` keys accept any element. A string still draws a boxed cap, an element draws bare. New `MouseIcon` draws a mouse with the left, right or wheel button filled. `ListItem` takes `selected` and forwards its other attributes, a selected item fills with `--theme-accent`. New `Tabs` renders a `tablist` with a selected state and arrow key movement.
  
  A `theme` with an `ink` key now also sets `color: var(--theme-ink)` on the element. Before, only the variable changed, and the text kept the inherited color. This is a visible change for any element that passed `theme={{ ink }}` and relied on the variable alone.
  
  Add `sacred-solid/themes/redline.css` with `theme-redline`, red ink and lines on a maroon-black page, a saturated red accent for selected rows and cyan keycaps. It sets a Rajdhani font stack.
- 8380205: Add `Panel`, a titled frame with an optional icon, title and meta header and a body. `tone` picks an outline header (a bottom line) or a filled header (`--theme-surface-inverse` with `--theme-ink-inverse` text). Add `KeyHint`, a row of keycaps with a label, drawn in `--theme-control-foreground`. `BarProgress` takes `variant="solid"`, a continuous fill over a track, and keeps `"char"` as the default. Add the `sacred-solid/themes/acid.css` stylesheet with `theme-acid`, a lime on near-black theme with slate highlights and cyan keycaps. It also sets `--font-family-mono` to a Rajdhani stack, so load the font in your page.
- 8380205: Every component now takes a `theme` prop. It is an object keyed by the camelCase role token names, typed from the token table, and it writes inline `--theme-*` variables that re-theme the subtree below the component. `themeTokens`, `ThemeProps` and `styleAttributes` are exported.
  
  `augAttributes` is gone. `styleAttributes(props, style)` takes an object with `aug` and `theme` and returns the attributes and merged style for a root element. A component with an aug border or inlay also gets `data-aug-border` and `data-aug-inlay`.
  
  Breaking. `Button` renamed its `theme="PRIMARY" | "SECONDARY"` prop to `variant`, so `theme` can carry tokens.
  
  An augmented element now drops its native chrome. With `aug.border` the native lines go, with `aug.inlay` the native fill goes, and with any `aug` the elevation shadow goes. Plain components nested inside keep their own chrome, and hover, focus and active states stay.
  
  Add the `surface-chip` role for labels, bars, nav and scrollbar thumbs. `surface-float` now fills only overlay panels. Themes must set `--theme-surface-chip`, and every built-in theme sets it to the old `surface-float` value.
  
  Add `sacred-solid/themes/holo.css`, a dark translucent theme with a cyan accent and glow shadows. Add the `Surface` component, a panel with an optional glow and backdrop blur.
- 8380205: Theming now uses a role token vocabulary, and the old token names are gone. Stylesheets in this package may now differ from the React originals.
  
  Breaking renames. `--theme-text` is split into `--theme-ink` (text), `--theme-line-strong` (edges) and `--theme-surface-inverse` (fills). `--theme-background` is split into `--theme-surface-page` and `--theme-ink-inverse` (text on an ink fill). `--theme-border` is split into `--theme-surface-float` (fills) and `--theme-line` (edges). `--theme-border-subdued` is split into `--theme-line-subdued`, `--theme-surface-subdued` and the shadow colors. `--theme-overlay` becomes `--theme-ink-subdued`, because only placeholder text used it. `--theme-window-shadow` becomes `--theme-shadow-window-color` and `--theme-surface-sunken`.
  
  The remaining renames are one to one. `--theme-background-input` is now `--theme-surface-input`, `--theme-background-modal` is `--theme-surface-panel`, `--theme-background-modal-footer` is `--theme-surface-panel-footer` and `--theme-window-background` is `--theme-surface-window`. `--theme-focused-foreground` is `--theme-accent` and `--theme-focused-foreground-subdued` is `--theme-accent-subdued`. `--theme-button`, `-button-text`, `-button-foreground` and `-button-background` are `--theme-control`, `-control-ink`, `-control-foreground` and `-control-background`.
  
  New constants cover line widths (`--theme-line-width-strong`, `--theme-line-width`, `--theme-line-width-double`) and shadow geometry (`--theme-shadow-window-geometry`, `-float-`, `-tooltip-` and `-ring-`), each paired with a per-theme color. A theme can now set translucent surfaces, hairline lines or a glow instead of a hard offset shadow. Every default theme and tint computes to the same colors as before. The token names are exported as a typed table from `src/theme/tokens.ts`.
